Server Security Guide

A working app is not automatically safe to expose. This guide maps five common internet-facing failures to the controls used by the hardened demo.

Educational simulator. Vulnerable outcomes are local fixtures and deterministic replays. Render runs only the hardened edge and backend.

Start here

What this demo proves

The vulnerable stack publishes internal services, trusts hostile request metadata, serves hidden files, accepts unbounded work, and welcomes obvious scanners. The hardened stack exposes only the public edge, filters at the boundary, limits work, and keeps internal services unreachable.

Open first case: exposed AI service

Five attack paths

Incident map

Case 01 · Service boundary

Exposed internal AI service

A published model endpoint turns server compute and bandwidth into an anonymous public utility.

Fix
Publish only ports 80/443. Put AI, database, and cache services on private networks with no host bindings.
Run live 404 check
Case 02 · Headers

Forged middleware header

Framework internals must not become a user-controlled authorization switch.

Fix
Reject x-middleware-subrequest at the edge, patch framework versions, and enforce authorization inside trusted handlers.
Run live 403 check
Case 03 · Static files

Dotfile probe

Generic static serving can expose environment, VCS, SSH, or cloud configuration paths.

Fix
Use explicit asset allowlists and deny hidden configuration paths before proxying.
Run live 404 check
Case 04 · Resilience

Unbounded job flood

Small requests can cause expensive work when no edge or process ceilings exist.

Fix
Rate-limit bursts, cap connections, and set memory, CPU, and PID ceilings. The Lab replays this case without flooding Render.
Replay flood policy
Case 05 · Noise reduction

Known scanner traffic

Obvious scanners are not the whole threat model, but dropping them reduces noise and cheap probing.

Fix
Filter known signatures at the edge. Never treat user-agent filtering as authentication or a complete WAF.
Replay scanner policy

Limits

What this demo does not claim

  • Local counters do not replace a distributed rate limiter.
  • User-agent filtering does not replace authentication, authorization, or a full WAF.
  • Fake fixtures contain no credentials and no real model pull.
  • Render free instances can sleep; cold starts can delay first request.
